\section{Objectif}
% ==============================================================================

Implémenter un \textbf{tas max} en C++ (\texttt{src/10\_tas\_max.cpp}), y insérer les
valeurs d'un fichier (200\,000, 1\,000\,000 puis 10\,000\,000 valeurs), puis mesurer le temps
et le nombre d'échanges de trois opérations sur le tas construit :
\textbf{extraire le maximum une fois} (retirer la racine, puis réorganiser le tas),
\textbf{insérer une valeur qui reste à la fin} (aucune réorganisation) et
\textbf{insérer une valeur qui remonte jusqu'à la racine} (vérifiée à chaque niveau).
Puis comparer avec le tas de la STL, \texttt{std::priority\_queue}.

\section{Un arbre rangé dans un tableau}
% ==============================================================================

Un tas max est un arbre binaire \textbf{complet} (rempli niveau par niveau, de gauche à
droite) qui respecte une seule règle : \textbf{chaque parent est plus grand que ses
enfants}. Le maximum est donc toujours à la racine.

Comme l'arbre est complet, on le range dans un simple \texttt{vector<int>}, sans pointeurs.
Pour la case $i$ :

\begin{center}
\begin{tabular}{l l}
parent        & $(i - 1) / 2$ \\
enfant gauche & $2i + 1$ \\
enfant droit  & $2i + 2$ \\
\end{tabular}
\end{center}

\section{Insertion : on ajoute en bas, puis on remonte}
% ==============================================================================

\begin{lstlisting}[caption={Insertion (\texttt{inserer} et \texttt{monter}).}]
// Insertion : ajoute la valeur dans la premiere case libre (a la fin),
// puis la fait remonter. O(log n).
void inserer(int val) {
    tas.push_back(val);
    monter(tas.size() - 1);
}

// Fait remonter la case i : tant qu'elle est plus grande que son parent,
// on les echange. S'arrete a la racine ou quand le parent est plus grand.
void monter(int i) {
    while (i > 0 && tas[(i - 1) / 2] < tas[i]) {
        swap(tas[i], tas[(i - 1) / 2]);
        echanges++;
        i = (i - 1) / 2;
    }
}
\end{lstlisting}

La nouvelle valeur est placée dans la première case libre (à la fin du tableau). Tant
qu'elle est plus grande que son parent, on les \textbf{échange} : elle remonte d'un
niveau. Elle s'arrête quand son parent est plus grand, ou à la racine.

Exemple : on insère dans l'ordre $10, 4, 15, 20, 8, 30$. Voici l'insertion de \textbf{20}
dans le tas $[15, 4, 10]$ (en vert la valeur qui remonte, en orange la case comparée, en
rouge l'échange) :

Une insertion a donc un \textbf{meilleur cas} et un \textbf{pire cas}, que le programme
mesure tous les deux une fois le tas construit :
\begin{itemize}
  \item \textbf{la valeur reste à la fin} (comme 8 ci-dessus) : elle est plus petite que
        son parent, une seule comparaison suffit, \textbf{0 échange}, $O(1)$ ;
  \item \textbf{la valeur remonte jusqu'à la racine} (comme 30) : elle est plus grande que
        toutes les autres, il faut la vérifier et l'échanger à chaque niveau,
        \textbf{$\log_2 n$ échanges} (17 pour 200\,000 valeurs), $O(\log n)$.
\end{itemize}
Les $n$ insertions du fichier coûtent donc au pire $O(n \log n)$.

\section{Extraction : on retire la racine, puis on redescend}
% ==============================================================================

\begin{lstlisting}[caption={Extraction du maximum (\texttt{extraireMax} et \texttt{descendre}).}]
// Extraction : retire et renvoie la racine (le max). Le dernier element
// prend sa place, puis on l'ajuste en le faisant descendre. O(log n).
int extraireMax() {
    int racine = tas[0];
    tas[0] = tas.back();
    tas.pop_back();
    if (!tas.empty()) descendre(0);
    return racine;
}

// Fait descendre la case i : on l'echange avec le plus grand de ses deux
// enfants tant qu'il est plus grand qu'elle. S'arrete quand elle est a sa
// place ou qu'elle n'a plus d'enfant.
void descendre(int i) {
    int n = tas.size();
    while (true) {
        int max = i;
        int g = 2 * i + 1;
        int d = 2 * i + 2;
        if (g < n && tas[g] > tas[max]) max = g;
        if (d < n && tas[d] > tas[max]) max = d;
        if (max == i) return;
        swap(tas[i], tas[max]);
        echanges++;
        i = max;
    }
}
\end{lstlisting}

Le maximum est la racine. Pour ne pas laisser de trou, on met le \textbf{dernier} élément
à la racine et on raccourcit le tableau. Cet élément est petit, donc la règle n'est plus
respectée : on l'\textbf{ajuste} en l'échangeant avec le plus grand de ses deux enfants,
jusqu'à ce qu'il soit plus grand que ses enfants ou qu'il n'en ait plus.

\textbf{Interprétation.}
\begin{itemize}
  \item \textbf{Insertions, fichier trié : le pire cas.} Chaque valeur remonte
        \textbf{jusqu'à la racine} : 15,7 échanges par valeur pour 200\,000 valeurs, 21,3
        pour 10\,000\,000 ($\log_2 n$ : 17,6 et 23,3). Mélangées, une valeur s'arrête
        presque tout de suite : 1,3 échange par valeur, \textbf{quel que soit $n$}.
  \item \textbf{Avec plus de données, l'écart trié / mélangé grandit} : le cas trié est
        1,25 fois plus lent à 200\,000 valeurs, 1,4 fois à 1\,000\,000 et \textbf{1,6 fois
        à 10\,000\,000} (711 contre 453~ms). Probablement parce que le tableau (0,8~Mo, puis
        4~Mo) tient d'abord dans le cache du processeur, ce qui rend les échanges
        supplémentaires peu coûteux, alors qu'à 10\,000\,000 valeurs il fait 40~Mo et ne
        tient plus dans les 8~Mo du cache L3.
  \item \textbf{Insertion qui reste à la fin : 0 échange, environ 0,1~$\mu$s, quel que soit
        $n$.} Une seule comparaison avec le parent suffit : c'est le meilleur cas, $O(1)$.
  \item \textbf{Insertion jusqu'à la racine : $\log_2 n$ échanges} (17, 19 puis 23) et
        environ 0,2~$\mu$s. Multiplier $n$ par 50 n'ajoute que 6 échanges : c'est le
        $O(\log n)$. Elle reste plus rapide qu'une extraction, qui compare deux enfants à
        chaque niveau au lieu d'un parent.
  \item \textbf{Extraction du max : 16 à 22 échanges}, moins d'une microseconde sur le
        fichier trié. Sur les valeurs mélangées à 10\,000\,000, elle monte à 4~$\mu$s : le
        chemin descendu traverse des cases éloignées en mémoire (même explication de cache,
        non vérifiée).
  \item Ces opérations uniques durent 0,1 à 4~$\mu$s, près de la précision de l'horloge :
        leur mesure varie beaucoup d'une exécution à l'autre, d'où les médianes.
\end{itemize}

\section{Comparaison avec \texttt{std::priority\_queue}}
% ==============================================================================

La STL fournit déjà un tas max : \texttt{std::priority\_queue<int>}. Il range aussi les
valeurs dans un \texttt{vector}, et \texttt{top()} renvoie toujours le maximum. Le
programme 11 contient les \textbf{deux versions dans le même fichier} (notre classe
\texttt{TasMax}, sans le compteur d'échanges, et \texttt{priority\_queue}) et les mesure
l'une après l'autre sur les mêmes valeurs (les mêmes quatre mesures que le programme 10),
puis affiche la plus rapide. \texttt{push(v)} remplace \texttt{inserer(v)},
\texttt{top()} remplace \texttt{max()} et \texttt{pop()} remplace \texttt{extraireMax()}.

\textbf{Interprétation.}
\begin{itemize}
  \item \textbf{Même structure, mêmes ordres de grandeur.} Les deux versions sont un tas
        dans un \texttt{vector} et font le même travail : $O(\log n)$ par opération.
  \item \textbf{Insertion des $n$ valeurs : notre version gagne, sur les trois tailles.}
        1,4 fois plus vite sur le fichier trié, à chaque exécution (15 sur 15) : à
        10\,000\,000 valeurs, cela fait \textbf{283~ms de moins} (707 contre 990~ms). Sur les
        valeurs mélangées, l'avance est faible mais régulière ($\times 1{,}06$ à $1{,}08$,
        13 ou 14 victoires sur 15).
  \item \textbf{Opérations uniques : égalité.} Extraire le max, insérer une valeur qui reste
        à la fin ou qui remonte jusqu'à la racine prend 0,1 à 4~$\mu$s : les deux versions
        font les mêmes comparaisons et les mêmes échanges, et l'écart se perd dans la
        précision de la mesure.
  \item \textbf{\texttt{priority\_queue} est-elle meilleure partout ?} Non, pas sur ces
        mesures : même avec 10\,000\,000 de valeurs, elle n'est jamais nettement plus rapide,
        et elle perd l'insertion des $n$ valeurs.
        Elle reste le bon choix en pratique (déjà écrite, testée et générique) ; écrire
        notre propre tas permet de comprendre ce qu'elle fait et de compter les échanges,
        ce que \texttt{priority\_queue} ne permet pas.
\end{itemize}

% ==============================================================================
\section{Conclusion}
% ==============================================================================

Le tas max se range dans un simple tableau : le parent de la case $i$ est la case
$(i-1)/2$. L'insertion fait \textbf{remonter} la nouvelle valeur, l'extraction fait
\textbf{redescendre} le dernier élément placé à la racine, et chacune coûte au plus la
hauteur de l'arbre, $\log_2 n$. Une insertion qui reste à la fin ne fait aucun échange ;
une insertion qui remonte jusqu'à la racine en fait $\log_2 n$ (23 pour 10\,000\,000
valeurs), en 0,1 à 0,2~$\mu$s. Insérer les $n$ valeurs prend environ 10~ms pour 200\,000 valeurs
et 0,45 à 0,7~s pour 10\,000\,000 ; des valeurs triées sont le pire cas, avec 12 à 17 fois plus
d'échanges, et l'écart de temps grandit avec $n$ (1,6 fois plus lent à 10\,000\,000).
\texttt{std::priority\_queue} est la version STL de la même structure : à égalité sur les
opérations uniques, et plus lente que la nôtre pour insérer les $n$ valeurs.
