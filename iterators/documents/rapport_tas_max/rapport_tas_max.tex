\section{Un arbre rangé dans un tableau}
% ==============================================================================

Un tas max est un arbre binaire \textbf{complet} (rempli niveau par niveau, de gauche à
droite) qui respecte une seule règle : \textbf{chaque parent est plus grand que ses
enfants}. Le maximum est donc toujours à la racine.

Comme l'arbre est complet, on le range dans un simple \texttt{vector<int>}, sans pointeurs.
Pour la case $i$ :

\begin{center}
\begin{tabular}{l l}
parent        & $(i - 1) / 2$ \\
enfant gauche & $2i + 1$ \\
enfant droit  & $2i + 2$ \\
\end{tabular}
\end{center}

\section{Insertion : on ajoute en bas, puis on remonte}
% ==============================================================================

\begin{lstlisting}[caption={Insertion (\texttt{inserer} et \texttt{monter}).}]
// Insertion : ajoute la valeur dans la premiere case libre (a la fin),
// puis la fait remonter. O(log n).
void inserer(int val) {
    tas.push_back(val);
    monter(tas.size() - 1);
}

// Fait remonter la case i : tant qu'elle est plus grande que son parent,
// on les echange. S'arrete a la racine ou quand le parent est plus grand.
void monter(int i) {
    while (i > 0 && tas[(i - 1) / 2] < tas[i]) {
        swap(tas[i], tas[(i - 1) / 2]);
        echanges++;
        i = (i - 1) / 2;
    }
}
\end{lstlisting}

La nouvelle valeur est placée dans la première case libre (à la fin du tableau). Tant
qu'elle est plus grande que son parent, on les \textbf{échange} : elle remonte d'un
niveau. Elle s'arrête quand son parent est plus grand, ou à la racine.

Exemple : on insère dans l'ordre $10, 4, 15, 20, 8, 30$. Voici l'insertion de \textbf{20}
dans le tas $[15, 4, 10]$ (en vert la valeur qui remonte, en orange la case comparée, en
rouge l'échange) :

% ==============================================================================
\section{Extraction : on retire la racine, puis on redescend}
% ==============================================================================

\begin{lstlisting}[caption={Extraction du maximum (\texttt{extraireMax} et \texttt{descendre}).}]
// Extraction : retire et renvoie la racine (le max). Le dernier element
// prend sa place, puis on l'ajuste en le faisant descendre. O(log n).
int extraireMax() {
    int racine = tas[0];
    tas[0] = tas.back();
    tas.pop_back();
    if (!tas.empty()) descendre(0);
    return racine;
}

// Fait descendre la case i : on l'echange avec le plus grand de ses deux
// enfants tant qu'il est plus grand qu'elle. S'arrete quand elle est a sa
// place ou qu'elle n'a plus d'enfant.
void descendre(int i) {
    int n = tas.size();
    while (true) {
        int max = i;
        int g = 2 * i + 1;
        int d = 2 * i + 2;
        if (g < n && tas[g] > tas[max]) max = g;
        if (d < n && tas[d] > tas[max]) max = d;
        if (max == i) return;
        swap(tas[i], tas[max]);
        echanges++;
        i = max;
    }
}
\end{lstlisting}

Le maximum est la racine. Pour ne pas laisser de trou, on met le \textbf{dernier} élément
à la racine et on raccourcit le tableau. Cet élément est petit, donc la règle n'est plus
respectée : on l'\textbf{ajuste} en l'échangeant avec le plus grand de ses deux enfants,
jusqu'à ce qu'il soit plus grand que ses enfants ou qu'il n'en ait plus.

Une extraction descend au plus de $\log_2 n$ niveaux : elle coûte $O(\log n)$. Après la
réorganisation, la racine contient le nouveau maximum, prêt pour l'extraction suivante. Le
programme extrait le maximum \textbf{une seule fois}, après avoir inséré les 200\,000 valeurs.

\section{Résultats}
% ==============================================================================

Machine : Intel Core i5-1135G7, Linux, \texttt{g++} 15.2, \texttt{-std=c++17 -O3}.
Le fichier \texttt{data/data.txt} contient $3, 6, 9, \dots, 600\,000$ : 200\,000 valeurs
\textbf{triées par ordre croissant}. Le programme les utilise telles quelles, puis
mélangées (\texttt{std::shuffle}, graine 42). La lecture du fichier n'est pas chronométrée.

\textbf{Interprétation.}
\begin{itemize}
  \item \textbf{Insertions, fichier trié : le pire cas.} Chaque nouvelle valeur est plus
        grande que toutes les autres, donc elle remonte \textbf{jusqu'à la racine} :
        3\,137\,875 échanges, soit environ 15,7 par valeur (proche de $\log_2 200\,000 \approx 17$).
  \item \textbf{Insertions, valeurs mélangées.} Une valeur au hasard est en général plus
        petite que son parent et s'arrête tout de suite : 256\,598 échanges, environ
        1,3 par valeur, \textbf{12 fois moins}. Pourtant le temps est presque le même
        (7,1 contre 6,9~ms) : probablement parce que, dans le cas trié, la boucle de
        \texttt{monter} se comporte toujours de la même façon (le processeur prédit
        parfaitement le test) et parcourt le haut du tableau, qui reste en cache.
  \item \textbf{Extraction du max : 16 ou 17 échanges, moins d'une microseconde.} Le
        dernier élément placé à la racine est petit et redescend presque jusqu'en bas :
        16--17 échanges, c'est bien $\log_2 n$. La racine 600\,000 est retirée et, après la
        réorganisation, le nouveau max 599\,997 est à sa place. Une extraction est environ
        \textbf{15\,000 fois plus rapide} que les 200\,000 insertions.
  \item Une seule extraction dure si peu (0,3 à 0,6~$\mu$s) que sa mesure varie beaucoup d'une
        exécution à l'autre : d'où les médianes.
\end{itemize}

\section{Comparaison avec \texttt{std::priority\_queue}}
% ==============================================================================

La STL fournit déjà un tas max : \texttt{std::priority\_queue<int>}. Il range aussi les
valeurs dans un \texttt{vector}, et \texttt{top()} renvoie toujours le maximum. Le
programme 11 contient les \textbf{deux versions dans le même fichier} (notre classe
\texttt{TasMax}, sans le compteur d'échanges, et \texttt{priority\_queue}) et les mesure
l'une après l'autre sur les mêmes valeurs (insertions, puis une extraction du max), puis
affiche la plus rapide :

\centering
\begin{tabular}{l l l}
\toprule
\textbf{Opération} & \textbf{Notre \texttt{TasMax}} & \textbf{\texttt{priority\_queue}} \\
\midrule
Insérer          & \texttt{inserer(v)}     & \texttt{push(v)} \\
Lire le max      & \texttt{max()}          & \texttt{top()} \\
Retirer le max   & \texttt{extraireMax()}  & \texttt{pop()} \\
\bottomrule
\end{tabular}
\caption{Les deux versions, opération par opération (toutes en $O(\log n)$, sauf lire le max en $O(1)$).}
\end{table}

d'exécutions la version la plus rapide a gagnées.}
\end{table}

\textbf{Interprétation.}
\begin{itemize}
  \item \textbf{Même structure, mêmes ordres de grandeur.} Les deux versions sont un tas
        dans un \texttt{vector} et font le même travail : $O(\log n)$ par opération.
  \item \textbf{Fichier trié : notre version gagne.} Elle insère 1,4 fois plus vite à
        chaque exécution (15 sur 15), et extrait le max un peu plus vite (11 sur 15).
  \item \textbf{Valeurs mélangées : égalité.} \texttt{priority\_queue} gagne le plus souvent
        les insertions, mais de 2\,\% seulement ; pour l'extraction, aucune version ne se
        détache (8 victoires contre 7).
  \item \textbf{\texttt{priority\_queue} est-elle meilleure partout ?} Non, pas sur ces
        mesures : elle n'est jamais nettement plus rapide, et elle perd sur le fichier trié.
        Elle reste le bon choix en pratique (déjà écrite, testée et générique) ; écrire
        notre propre tas permet de comprendre ce qu'elle fait et de compter les échanges,
        ce que \texttt{priority\_queue} ne permet pas.
\end{itemize}

% ==============================================================================
\section{Conclusion}
% ==============================================================================

Le tas max se range dans un simple tableau : le parent de la case $i$ est la case
$(i-1)/2$. L'insertion fait \textbf{remonter} la nouvelle valeur, l'extraction fait
\textbf{redescendre} le dernier élément placé à la racine, et chacune coûte au plus la
hauteur de l'arbre, $\log_2 n$. Sur 200\,000 valeurs, les insertions prennent environ 7~ms,
et une extraction du max moins d'une microseconde (16--17 échanges). Des valeurs triées sont le pire cas des insertions
en nombre d'échanges (12 fois plus), sans gros écart de temps sur cette taille.
\texttt{std::priority\_queue} est la version STL de la même structure : à égalité sur les
valeurs mélangées, et un peu plus lente que la nôtre sur le fichier trié.
